Living epic / tracking home for **class materials upload** (textbook + personal).
Phase 1+2 (in-plan PDF) are shipped; this file remains the status board and
decision log. Product strategy: [`docs/pm_hub.md`](../docs/pm_hub.md). Roadmap

`material_ids`, scratch-outside-wiki). Year-start class library browse /
“use chapter 1” = Phase 3 follow-up.

---

## Purpose

Let a teacher upload photographed, scanned, or PDF material into a class and get
OCR'd, reviewable, citable content for planning — without retyping and without
silently writing durable class memory.

## Scope (first slices)

- **In-plan upload first** (year-start library designed now, built later).
- Two sibling arms: **Textbook** (chapterized) vs **Personal** (per-lecture /
  lesson-linked), chosen by a UI toggle on upload.
- OCR via **Mistral OCR 4 only** for the first runtime slice. **PDF only**
  (Word/PPT/tablet = export PDF first).
- Plan-scratch artifacts → promote into class materials on **plan save**.
- Materials as a **source/citation layer**, separate from curriculum
  `wiki/sources` trusted sources (reuse mechanics, not the same registry/tools).

## Non-goals

- Autonomous conversion of uploads into durable wiki facts.
- LlamaParse (or other third-party OCR vendors) in the first slice.
- Docling as a first-slice runtime dependency (later optional backup only).
- Open-web / “all textbooks” corpus before licensing constraints are solved.
- Vector DB as the default retrieval path.
- Full year-start library UX before in-plan upload works end-to-end.

## Architecture sketch (Option 1)

### Wiki layout (current)

```
wiki/classes/{class_id}/
  materials/
    textbooks|personal/
      {material_id}/
        source.pdf                 # original upload (reference only)
        summary.md                 # wiki-friendly stub + inventory
        document.agent.md          # assembled OCR MD
        assets/
          manifest.json
          img-*.jpeg
          tbl-*.html
          tbl-*.jpg                # PDF table bbox crops (Lewis etc.)
        important_images.json
        provenance.json            # checksum/model/usage; NO base64
  lessons/{YYYY-MM-DD}/
    lesson_plan.md
    materials.json                 # { "material_ids": ["..."] }
```

Curriculum trusted sources remain under `wiki/sources` (LehrplanPLUS, etc.).
Class materials never share that registry id space.

### Plan-scratch lifecycle

1. Teacher uploads in Plan (toggle Textbook vs Personal).
2. Backend runs Mistral OCR 4 → writes **session/plan scratch** artifact trio
   (not yet durable class materials).
3. Planner may read scratch via materials-scoped tools / context (compact TOC +
   progressive section read; raw behind `raw_ref`-style capture).
4. On **plan save**, promote scratch into
   `materials/{textbooks|personal}/{id}/`. Debug dumps (`raw_response.json`,
   `document_annotation.json`) stay in scratch and are not copied into the wiki.
5. Discarded plans / abandoned uploads GC scratch (policy TBD; not in this slice).

### Promote rules (shipped)

- Promote copies the artifact trio + provenance into the class materials tree.
  Debug OCR JSON is not copied.
- Personal materials get a lesson date link via `lessons/{date}/materials.json`.
- Textbooks keep a summary/section TOC for progressive read; full chapterize
  is Phase 3.
- Plan-scoped-only vs standing library flags wait on year-start library UX.
- Promotion never writes `course_state`, roster, diary, or other curated memory
  pages.

### Context packs / tools (separation from trusted sources)

- Reuse the proven pattern: compact TOC/index in context; list/search/read tools;
  provenance on citations.
- **Do not** overload `trusted_sources.md`, `list_trusted_sources`, or
  `wiki/sources` paths.
- Compact materials TOC in plan chat + `list_class_materials` /
  `search_class_materials` / `read_class_material`. Cite `Material: material_id`.
- Citation namespace must distinguish materials vs curriculum sources vs class
  memory wiki pages.

### Memory-safety

- Default: materials are evidence/citation, not compiled class memory.
- Durable memory facts still flow only through Update Memory / MemV4
  (`remember` → ledger → Sweep → teacher-approved apply).
- Plans should paraphrase/adapt into self-contained lesson text; end citations
  stay light (page/section pointers), assuming the teacher has the material.

engine.

  and offline / self-hosted extraction.
- **LlamaParse** — out of slice.
