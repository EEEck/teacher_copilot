# Your First Session

**So what:** One guided pass through the mock class proves the core loop — plan from memory, teach, log results, review what saves.

The beta uses a seeded mock class: **Chemie 9b**. Every tester starts from the same realistic notebook so you can focus on the workflow, not on building memory from scratch.

## Why a mock class

The mock class includes a current unit, recent lessons, known misconceptions, open loops, saved plans, and compact memory the copilot loads automatically. The details are realistic enough to test planning and review — they are not your real students.

> [!note]
> Feedback that helps most: Did the plan use the right memory? Was the memory update trustworthy? How much did you edit before saving?

## 20-minute walkthrough

> [!blueprint]
> **Session blueprint**
> 1. **Open Chemie 9b** — From the class list. Scan class home and the lesson timeline. *You should see unit context, open loops, and recent lessons without opening raw files.*
> 2. **Create a next lesson plan** — Use Create lesson plan. Ask in plain language, e.g. “Plan the next 45-minute lesson after the redox review.” *The draft should reflect recent lessons and misconceptions.*
> 3. **Save the plan** — Pick a lesson date and save. Review the plan diff before confirming. *The plan appears on that date in the timeline.*
> 4. **Add lesson results** — Open the planned lesson → Add lesson results. Describe what actually happened in a short recap. *The copilot drafts structured results; it does not save until you approve.*
> 5. **Review and commit memory** — Check proposed wiki file changes. Reject or edit anything wrong. Save only what you trust. *Future plans can use this approved memory.*
> 6. **Return to class home** — Confirm the timeline and context updated as expected.

## Good prompts to try

For planning:

- “Plan the next 45-minute lesson after the redox review.”
- “Prepare a lesson that checks whether they can assign oxidation numbers.”
- “Make this more active — they struggled with balancing equations last time.”

For memory update:

- What was taught and what students understood
- Where they struggled and what explanation worked
- Homework, tests, open loops, or follow-up tasks

> [!tip]
> Timeline shortcuts reduce setup: planned lessons → Add lesson results; taught lessons → Correct with agent. Known dates start with the target selected; unknown dates still need confirmation.

## What to report during beta

Useful feedback is specific:

- Did the plan use the right class memory?
- Did the memory update capture the right facts?
- Were proposed changes easy to trust?
- How much editing did you need before saving?
- Was the lesson target or date ever confusing?
- Did the product feel like it saved time?
